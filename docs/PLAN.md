# knowledge-log — build plan

## Context
Study Reels Generator (SRG, `~/Projects/Study Reels Generator`) turns PDF notes into character reels. It uses Gemini for scripts, and Piper/RunPod voice cloning plus ffmpeg for rendering. knowledge-log is a new, more personal app built next to it, with two tabs:
1. **Quiz:** 10 MCQs a day, repeated until the score reaches the pass % set in Settings.
2. **Reels:** two categories.
   - **Following:** YouTube Shorts and Instagram Reels from accounts listed in Settings.
   - **My Notes:** reels generated from the user's own PDF notes. Each chunk is routed to one of three kinds:
     - **2a** character reel, using the SRG renderer.
     - **2b** manim explainer (needs R&D).
     - **2c** diagram plus voiceover.

> **Update 2026-09-24: how the pipeline runs now.** MCQ generation no longer uses LangGraph or
> the Agent SDK. A deterministic step engine (`kl mcq`) claims work from a Django planner over
> `/api/pipeline/*`, and a Claude Code session (the `/mcq-generation` skill) does the reading and
> writing, with fresh subagents as critics. Postgres is the only store. The Mac's runner pulls work
> and starts the session, or you start one from Claude Code. See
> [`PIPELINE_DB.md`](PIPELINE_DB.md) and the Obsidian note *Pipeline Runners Architecture*. The
> manim reels (2b) now run this way too (`kl reel`, `/reel-generation`, since 2026-09-24), capped at 5
> reels for now and shown in the Reels tab. The LangGraph and Agent SDK design below still describes
> the 2a and 2c reel pipelines until they are designed the same way.

Content is generated by a **LangGraph graph** that a Claude Code plugin starts and that also runs on a schedule on the Mac through launchd. Its LLM nodes call **Claude through the Claude Agent SDK**, which uses the local Claude Code login. Each run keeps going until it has made **10 reels and 10 MCQs** (both configurable). It also stops early if the Claude usage window runs out, and the next run resumes where it stopped. Each piece of content goes through **reflection loops**: a writer drafts it, a critic checks it against the source notes, and the draft is revised.

Progress is kept in Postgres in two places:
- **Domain tables:** per-document progress, the way SRG does it.
- **The LangGraph Postgres checkpointer:** lets a run that was cut off resume mid-graph.

Decisions made so far:
- **Notes:** PDFs only.
- **Codebase:** a new app that reuses SRG's renderer without modifying SRG.
- **Social videos:** discovered by a script and played through official embeds (pivot later if needed).
- **Runner:** local launchd for now, a cloud routine later.
- **MCQs:** the graph writes and stores them. The web app checks pass or fail.
- **Hosting:** deferred, so local Docker Compose and local or R2 storage for now.
- **Backend (2026-09-23):** Django + Django REST Framework on Postgres 16. One JSON API serves the web app now and a mobile app later.
- **Web app (2026-09-23):** React (Vite) + Tailwind v4, installable as a PWA. Mobile-first: bottom tab navigation on phones, side navigation on wider screens.

**Jev** is TypeSafe AI's "System One" decision model. Released 15 Sep 2026, early access. It takes text and returns typed Choice, Score or true/false answers, with probabilities and confidence. Input costs about $0.042 per million tokens and output is free. It is used for the two cheap classification jobs: educational vs spam, and routing to 2a/2b/2c. It sits behind a `Classifier` interface with a Claude fallback, because early access may not be granted straight away.

**Agent SDK auth caveat:** Anthropic's docs forbid *third-party products* from offering claude.ai login. Using your own Claude Code login locally for a personal tool is the intended setup here. The graph's LLM layer is an adapter (`kl/llm.py`), so switching to `ANTHROPIC_API_KEY`, which a future cloud routine needs anyway, is a config change.

## Stack (mirrors SRG so its code can be reused)
- **backend/:** Django 5 + Django REST Framework, psycopg 3, Postgres 16. Changed on 2026-09-23 from FastAPI + SQLAlchemy, so the web app and a future mobile app share one API.
  - Django owns the schema through its migrations. There are two apps:
    - `content`: documents, chunks, generation runs and questions.
    - `quiz`: quiz sets, attempts and settings.
  - The API lives under `/api/` and is stateless JSON, so a React Native or native client can use it unchanged.
  - Auth arrives with hosting: DRF token auth, which works for both web and mobile.
  - When reels need storage, copy SRG's `shared/storage.py` pattern (`LocalDiskStorage`, `R2Storage`).
- **ui/:** React + Vite + TypeScript + Tailwind v4, installable as a PWA. Changed on 2026-09-23 from Next.js, because Django owns the server.
  - Mobile-first. On phones, Quiz, Reels and Settings sit in a bottom tab bar. From 1024px wide, the same items move into a side navigation rail.
  - Data goes through TanStack Query and a typed API client in `ui/src/api/`. The client doesn't depend on React, so a future mobile app can reuse its types.
  - The reels feed follows SRG's `frontend/app/feed/page.tsx` swipe pattern (IntersectionObserver).
- **pipeline/:** Python package `kl` (uv) with a typer CLI.
  - The LangGraph graphs, Jev client, renderers and SRG bridge all live here.
  - Dependencies: `langgraph`, `langgraph-checkpoint-postgres`, `claude-agent-sdk`, `pydantic`, `pymupdf`, `yt-dlp`, `manim` (Phase 6).
  - The pipeline writes to the same Postgres tables as Django (`documents`, `chunks`, `generation_runs`, `questions`) through SQLAlchemy models that match Django's. Django's migrations own the schema, and SQLite is kept for local tests only.
- **plugin/knowledge-log/:** Claude Code plugin. It is a thin front door and holds all prompts, as skills (see the plugin-structure skill in `.claude/skills/plugin-structure`).
- **infra/docker-compose.yml:** local Postgres, on a port other than SRG's 5433.

## Data model (Django migrations)
- `documents`: `id`, `filename`, `file_hash` (unique, so the same upload isn't processed twice), `storage_key`, `page_count`, `last_processed_page`. This is SRG's resume model.
- `note_chunks`:
  - Link and content: `document_id`, `page_start`, `page_end`, `title`, `text`, `text_hash`.
  - Routing: `route` (character|manim|diagram), `route_confidence`, `route_source` (jev|claude).
  - Progress: `status` (pending → routed → drafted → approved → rendered | failed | skipped), `error`.
  - `review_log` (jsonb): every draft, critique and verdict, one entry per round.
- `reels`: `chunk_id`, `kind`, `storage_key`, `duration_s`, `title`, `source_pages`, `created_at`. Like questions, each reel records the pages it teaches.
- `note_scopes` (one per document): `selected`, `page_from`, `page_to` (null means the last page), `include_quiz`, `include_reels`, plus a cached file size and modification time so the folder can be rescanned cheaply.
  - A question or reel is in scope when its PDF is selected, its type is ticked, and **every** page it comes from lies inside the range.
- `questions`: `chunk_id`, `set_id` (nullable until a set is assembled), `stem`, `options` (jsonb), `correct_index`, `explanation`.
- `quiz_sets`: `id`, `available_on` (date, unique), `run_id`.
- `quiz_attempts`: `set_id`, `answers` (jsonb), `score_pct`, `passed`, `created_at`.
- `settings`: a single row holding `pass_pct` (default 70), `max_revisions` (default 2), and other preferences.
- `followed_accounts`: `platform` (youtube|instagram), `handle`, `channel_id`, `active`.
- `social_videos`:
  - Source: `platform`, `external_id` (unique per platform), `url`, `embed_url`, `title`, `description`, `published_at`.
  - Classification: `label` (educational|spam|unsure), `confidence`, `status` (pending|approved|rejected).
- `views`: `reel_id` or `social_video_id`, `viewed_at`.
- `generation_runs`: `started_at`, `finished_at`, `chunks_done`, `stop_reason` (targets_met|usage_limit|no_content|error), `thread_ids`.
- LangGraph checkpoint tables are created by `PostgresSaver.setup()` in the same database.

## LangGraph design (pipeline/kl/graph/)

### Shared pieces
- **`kl/llm.py`, `claude_structured(skill, inputs, schema)`:**
  - Wraps `claude_agent_sdk.query()` with the node's skill prompt (loaded from `plugin/knowledge-log/skills/<name>/SKILL.md`), no tools, and `max_turns=1`.
  - Asks for JSON matching a Pydantic schema, validates it, and retries once on validation failure.
  - Translates usage-limit or rate-limit errors into `UsageLimitReached`.
- **`kl/classify.py`:** the `Classifier` protocol, with `JevClassifier` (Choice questions, confidence) and a `ClaudeClassifier` fallback.
- **Reflection helper (`reflect.py`):** a reusable subgraph factory, `make_reflective(writer_node, critic_node, max_rounds)`.
  - Flow: writer → critic → a conditional edge that ends if `verdict.pass` or `rounds >= max_rounds`, and otherwise returns to the writer with the critique in its state.
  - Every round is appended to `review_log`.
  - If the last round still fails, the item is marked `failed`, with the critique as the reason. Nothing unreviewed is published.

### Critic rubric
The critic is a separate skill, `critic`, run with a strict reviewer persona. It sees the source page text or images and the draft, and returns `{pass, issues[], severity}`. It checks:
- **Facts:** every claim can be traced to the source, and nothing is invented.
- **Coverage:** the key point of the chunk is actually taught.
- **Format:**
  - Narration of 60 seconds or less (about 150 words).
  - Character voices fit `character_description.md`.
  - Diagram sources parse.
  - MCQs have exactly one correct option, plausible distractors, and no "all of the above".
- **Tone:** playful but accurate.

### Graphs
1. **`weekly_run` (top level, `thread_id=run-<id>`):**
   - `start_run` → `pick_document` → `page_window` (the next N pages, using `extract_pages_with_images` copied from SRG `content_service/extract.py`).
   - Then `segment_topics`, a reflective Claude step (the writer splits the pages into topics, and the critic checks for gaps or overlap).
   - Then `persist_chunks`, and a fan-out with `Send` to `chunk_pipeline` for each chunk.
   - Then `advance_document` → `check_targets` (a conditional edge, see "Run stop conditions") → either loop back to `pick_document`, or go to `assemble_quiz_sets` → `finish_run`.
2. **`chunk_pipeline` (a subgraph per chunk):**
   - `route`: Jev, falling back to Claude below the confidence threshold.
   - A conditional edge then picks one of three reflective subgraphs:
     - `character_script`: writes the topic JSON that SRG `renderer.py --topic-json` accepts. Pairings rotate the way SRG's `characters.rotation_cycle` does.
     - `diagram_spec`: a list of scenes, each with Mermaid or Graphviz source and narration.
     - `manim_scene` (Phase 6): Manim CE `Scene` code plus narration.
   - `render`: a tool node, no LLM.
   - `render_fix` loop: a render error or a diagram parse error goes back to the writer with the traceback, up to 3 times. For manim and diagram videos, a `visual_check` critic looks at 3 extracted frames.
   - `upload_and_record` → `mcq_writer` (reflective: 2–4 questions per chunk) → `persist_questions`.
3. **`assemble_quiz_sets`:**
   - Takes unassigned questions, oldest first and mixed across chunks, in groups of 10.
   - Each group becomes a `quiz_set` for the next empty `available_on` date.
   - The web app then serves one set a day.

### Run stop conditions
A run keeps going until **both targets are met**: `target_reels` (default 10) new rendered reels and `target_mcqs` (default 10) new approved MCQs. Both targets are stored in `settings`. The graph state holds `reels_made` and `mcqs_made` counters.
- **Checks:**
  - `check_targets` runs after every chunk.
  - Before a fan-out, the graph only sends as many chunks as are still needed, so it doesn't overshoot.
  - Once the MCQ target is reached, `mcq_writer` is skipped for the remaining chunks. Once the reel target is reached, only MCQ writing continues.
- **The run also stops, recording a different `stop_reason`, when:**
  - `usage_limit`: Claude usage runs out.
  - `no_content`: no unprocessed pages are left in any document.
  - `error`: repeated failures, meaning N chunks in a row fail review or rendering.
- A run stopped for any reason other than `targets_met` is resumed by the next run. The next run finishes the targets before starting new ones.
- **Output and cadence:** 10 MCQs per run means one day's quiz set per run. `assemble_quiz_sets` writes it to the next empty `available_on` date. To get a new quiz every day, schedule launchd daily. The default here is daily, and weekly also works: when there's no set for a day, `GET /quiz/today` serves the latest set not yet passed.

### Running out of usage
- `UsageLimitReached` propagates out of the node. The runner catches it and records `stop_reason=usage_limit`.
- The checkpointer keeps every completed node, so the next run finds the unfinished threads (`generation_runs.thread_ids`) and resumes them before picking new pages.
- Domain writes are idempotent. They are keyed on `text_hash` and `chunk_id`, so a replayed node never duplicates rows.

## `kl` CLI
- `kl ingest <pdf>`: hash the file, store it, create the `documents` row.
- `kl generate [--max-chunks N] [--doc ID]`: run or resume `weekly_run`.
- `kl status`: documents, chunk status counts, review failures, and the last runs.
- `kl review <chunk_id>`: pretty-print a chunk's `review_log`.
- `kl social discover`: see Phase 5.
- `kl quiz seed <file>`: for testing the Quiz tab.

**SRG bridge (`kl/srg.py`):** runs SRG code as a subprocess under `SRG_PYTHON`, with `cwd=$SRG_ROOT/video_service`, the same way SRG's orchestrator isolates its `characters` modules. It exposes:
- `render_topic(topic_json, out)` via `renderer.py --topic-json`
- `tts.synthesize` / `voice_clone.synthesize_cloned`
- `captions.build_ass`

SRG itself is not changed.

## Plugin (plugin/knowledge-log/)
- `.claude-plugin/plugin.json`.
- **Commands:**
  - `commands/generate.md`: runs `kl generate` through Bash and summarises the result with `kl status`.
  - `commands/status.md` and `commands/ingest.md`.
- **Skills (the single source of truth for prompts, read by the graph nodes):** `topic-segmentation`, `character-script` (adapted from SRG `skills/script_generation/SKILL.md` and the pairings), `diagram-video`, `manim-scene`, `mcq-writing`, `critic`, `visual-check`, `route-fallback`.
- **Runner:**
  - `scripts/launchd/com.knowledge-log.weekly.plist` runs `scripts/weekly.sh` once a week.
  - The schedule is set in the plist: daily by default (see "Run stop conditions"), or weekly.
  - `weekly.sh` activates the venv, runs `kl generate`, and logs to `logs/`.
  - It doesn't need an interactive `claude` session, because the Agent SDK drives Claude from inside the graph.
- **Debugging (optional):** `langgraph.json` so `langgraph dev` (LangGraph Studio) can step through the graph visually.
